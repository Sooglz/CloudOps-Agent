# CloudOps Agent 开发踩坑复盘笔记

> 记录我在开发这个项目过程中遇到的技术难点和解决方案。
> 这份笔记的目的：①帮自己回顾；②面试时能讲出「我遇到过什么问题、怎么解决的」，
> 这比「我用过什么技术」更能体现工程能力。

---

## 一、环境类踩坑

### 1. Windows Git Bash 缺基础命令

**现象**：在 Git Bash 里跑 `ls`、`grep`、`tail`、`dirname` 等命令全部报「command not found」。

**原因**：本机 Git Bash 环境配置不完整，缺少 coreutils 等基础工具。

**解决**：改用 PowerShell 执行文件操作和目录列举。但这又引出下一个坑👇

### 2. PowerShell 命令不回显输出

**现象**：PowerShell 里执行命令有结果，但工具界面收不到回显文本。

**解决**：把命令输出用 `Out-File` 写到临时文件，再用文件读取工具读回来。虽然繁琐，但稳定可靠。

**教训**：调试环境问题比写业务代码更耗时。遇到工具链异常时，先确认「输出到底有没有产生」，再排查「输出去哪了」。

### 3. pip 安装 langchain-openai 卡死

**现象**：`pip install langchain-openai` 反复卡在「Installing collected packages: openai」这一步。

**根因分析**：不是超时，而是 pip 在「重装 openai 这个大包」时被阻塞（沙箱环境 + 大包拷贝）。

**解决**：分两步——
1. 先单独 `pip install openai`（成功）
2. 再 `pip install --no-deps langchain-openai`（跳过依赖检查，只装 145KB 的本体）

**教训**：安装卡住时，先定位「卡在哪个包」，再用 `--no-deps` 拆解依赖，而不是反复重试整个安装。

### 4. 删除项目时二进制文件被锁

**现象**：迁移项目到 D 盘后，删除 C 盘源项目时，`.pyd`、`.exe` 二进制文件删除失败。

**原因**：这些文件被系统进程（杀毒扫描 / 文件索引）短暂锁定。

**解决**：隔几秒重试，锁释放后删除成功。

**教训**：删除操作失败不一定有错，先确认「是不是文件被占用」，再决定重试或换方案，不要盲目用 `rm -rf` 硬删。

## 二、代码类踩坑

### 5. load_dotenv() 找不到 .env（关键坑）

**现象**：从 `src/` 目录运行脚本时，`load_dotenv()` 加载不到根目录的 `.env`，导致 API Key 读不到、报 `Missing credentials`。

**根因**：`load_dotenv()` 默认从「当前工作目录」找 `.env`。从 `src/` 运行时，工作目录是 `src/`，但 `.env` 在项目根目录。

**解决**：显式指定绝对路径：
```python
PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
load_dotenv(os.path.join(PROJECT_ROOT, ".env"))
```

**教训**：**相对路径永远是坑**。涉及文件定位时，用 `os.path.abspath(__file__)` 反推项目根目录，而不是依赖「当前工作目录」。

### 6. API Key 被覆盖丢失

**现象**：给 `.env` 添加智谱 Key 时，DeepSeek 的 Key 整个不见了。

**原因**：编辑 `.env` 时「覆盖」而非「追加」。

**解决**：重新补全配置。

**教训**：改配置文件前先看清楚当前内容；敏感配置（API Key）最好另存一份备份。这也是为什么 `.env` 要进 `.gitignore`——万一出错，版本控制里还有历史可查。

### 7. 参数 schema 要完整定义

**现象**：工具调用时，DeepSeek 有时传错参数。

**解决**：给每个工具的 `parameters` 完整定义 JSON Schema（`type`、`properties`、`required`），让大模型明确知道每个参数的类型和必填项。

**教训**：Function Call 的效果很大程度取决于 schema 写得清不清楚。参数描述越精确，大模型调用越准。

### 8. 多轮记忆失效（最典型的坑 ⭐）

**现象**：阶段① 的多轮记忆明明能用，但升级到阶段③（工具调用版）后，问「我叫什么名字」Agent 答不上来，记忆"失效"了。

**根因**：阶段③ 重写 Agent 时，`run()` 方法里把对话消息 `messages` 写成了**局部变量**，每次调用都重新创建，只包含「系统提示 + 当前这一轮的问题」，**没有携带之前的对话历史**。所以 Agent 每次都"失忆"。

**解决**：把 `messages` 从局部变量提升为**实例属性** `self.history`，在 `__init__` 里初始化（含 SystemMessage），`run()` 里持续累积 HumanMessage / AIMessage / ToolMessage。Agent 实例只要不销毁，历史就一直保存。

```python
# 修复前（每次 run 都新建，丢失历史）
messages = [SystemMessage(...), HumanMessage(user_input)]

# 修复后（history 持久保存）
self.history.append(HumanMessage(user_input))
response = self.llm_with_tools.invoke(self.history)
self.history.append(AIMessage(response.content))
```

**核心收获**：**大模型本身是无状态的**，它不会"记住"任何事。所谓"记忆"，本质是**把历史消息重新喂给大模型**。多轮记忆、上下文管理，是 Agent 开发里最容易踩、也最核心的概念之一。

### 9. get_pods 工具默认命名空间太窄（真实工具调用后暴露）

**现象**：问 Agent「集群里有哪些 pod」，它连查三遍才给出完整结果——前两遍都只查 `default` 命名空间（空的），第三遍才想到去查 `kube-system`。

**根因**：`get_pods` 工具默认 `namespace="default"`，而真实集群刚建好时 default 里没有业务 Pod，导致 Agent 每次都查空，要多轮追问才能"绕"到有内容的命名空间。

**解决**：把默认行为改为**查询所有命名空间**（`kubectl get pods -A`），并更新工具描述告诉大模型"留空即查全部"。改完一次提问就能返回全部 Pod。

**核心收获**：
- 工具的**默认参数设计直接影响 Agent 的决策效率**——默认值太窄，大模型就要多轮试错。
- 这个问题只有在接入**真实环境**后才会暴露（模拟数据永远有内容，看不出默认值的问题）。这也印证了「模拟工具验证机制、真实工具暴露细节」的演进价值。

## 三、架构设计类反思（最有价值的复盘）

### 10. 关键词检索 vs 向量检索的演进

**背景**：做 RAG 时，我一开始没有 Embedding API Key，于是先用「关键词检索」跑通了完整链路。

**关键问题**：关键词检索只能字面匹配。「容器崩了」和「CrashLoopBackOff」字面上零重合，但语义上是一回事——关键词检索匹配不到。

**升级**：拿到智谱 Embedding Key 后，接入 Chroma 向量数据库，用余弦相似度做语义匹配，成功命中。

**核心收获**：
- **先跑通，再优化**：不要一上来就追求完美方案，先用最简单的方式验证链路，再针对性升级。
- **可替换接口的价值**：我把「检索器」抽象成一个接口，关键词和向量两种实现。升级时只改一个分支，其他代码零改动。这个抽象让演进成本极低。

### 11. 模拟工具 vs 真实工具的演进

**背景**：做工具调用时，我本机还没装 Docker/K8s，于是先用「模拟工具」返回假数据，跑通 ReAct 循环。

**升级**：阶段④ 升级成真实命令（`kubectl get pods`、`docker ps`），但保留了「自动降级」——没环境时回退到模拟数据。

**核心收获**：**把「机制」和「实现」分离**。先验证「Agent 能不能正确决策调哪个工具、传什么参数」，再关心「工具内部到底怎么执行」。这样学习时能聚焦核心机制，不被环境问题干扰。

### 12. 为什么手写 ReAct 循环，而不用 LangChain 内置 Agent

**决策**：LangChain 有现成的 `AgentExecutor`，但我选择手写 ReAct 循环。

**原因**：内置方案是黑盒，看不到「思考→调用工具→观察→再思考」的每一步。手写循环代码量不大，但每一步都透明，能真正理解 Agent 的工作原理。

**收获**：学习阶段，「看清原理」比「少写代码」更重要。理解透了，以后用框架也能知道它内部在做什么、出问题能定位。

## 四、给未来的自己（几条原则）

1. **先跑通，再优化**：用最简单方案验证链路，再针对性升级。
2. **把机制和实现分离**：抽象出接口，让演进成本极低。
3. **绝对路径 > 相对路径**：文件定位永远用 `__file__` 反推。
4. **敏感配置不进版本控制、不进镜像**：`.env` 进 `.gitignore`，密钥用 `--env-file`/Secret 注入。
5. **遇到卡住，先定位根因，再动手**：安装卡住→定位卡在哪个包；删除失败→定位是否文件被锁。
