# CloudOps Agent · 云原生智能运维助手

> 一个结合「大模型 + RAG 知识库 + 云原生运维」的智能运维助手，用于简历作品集与 Agent 全流程学习。

---

## 一、项目定位

**一句话描述**：一个能用自然语言对话，帮你查询、诊断、操作 Linux / Docker / Kubernetes 环境的 AI 运维助手。

**为什么值得做（写在简历上的卖点）**：
1. 把「云计算技术」专业能力（Linux、Docker、K8s）与「AI Agent」前沿技术结合，差异化明显。
2. 完整覆盖 Agent 开发全流程，能证明你理解 Agent 的核心机制，而非只会调 API。
3. 全链路容器化部署，本身就是对云原生工程能力的展示。

**技术栈**：
- 语言：Python 3.11+
- Agent 框架：LangChain
- 大模型：国内免费 OpenAI 兼容接口（智谱 GLM / DeepSeek 等，按需选择）
- 向量数据库：Chroma（本地轻量，起步够用）
- 目标环境：WSL2 + Docker + Kubernetes（minikube / kind）
- 部署：Docker 容器化 + K8s 编排

## 二、项目架构

```
用户提问
   │
   ▼
┌─────────────────┐
│  LLM 推理引擎    │  意图识别 + 工具决策（LangChain Agent）
└────────┬────────┘
         │ Function Call
         ▼
┌─────────────────────────────────────┐
│            工具能力矩阵               │
│  RAG检索 │ kubectl执行 │ Linux诊断 │ 监控查询 │
└─────────────────────────────────────┘
         │
         ▼
┌─────────────────────────────────────┐
│      目标环境（全部容器化）            │
│  K8s集群 │ Docker容器 │ 向量数据库      │
└─────────────────────────────────────┘
```

**Agent 全流程闭环**：
`Prompt → 记忆(对话历史) → 推理(LLM) → 工具调用 → 观察(执行结果) → 迭代 → 输出`

## 三、四阶段开发路线（Agent 全流程学习主线）

### 阶段 ①　最小可运行 Agent（学会：Prompt、多轮记忆）
- 目标：接一个 LLM API，做一个能多轮对话的命令行脚本。
- 产出：`app.py`，能记住上下文，流畅对话。
- 验收：命令行里和它聊 10 句，它能记住前面说的话。

### 阶段 ②　接入 RAG 知识库（学会：Embedding、向量检索）
- 目标：把 Linux 常用命令手册、K8s 常见报错文档做成知识库。
- 产出：文档切分 → 向量化 → 存入 Chroma → 检索增强回答。
- 验收：问它「Pod 一直 CrashLoopBackOff 怎么办」，它能引用知识库里的准确内容回答。

### 阶段 ③　接入工具调用（学会：Function Call、观察-推理循环）
- 目标：让 Agent 能真正执行 `kubectl get pods`、`docker ps` 等只读命令。
- 产出：定义工具函数 + 安全白名单 + 让 LLM 自主决定调哪个工具。
- 验收：问「现在集群里有哪些 Pod 在运行？」，它真的去执行 kubectl 并返回真实结果。
- 安全设计：只读优先、危险操作（删除/重启）需二次确认。

### 阶段 ④　容器化部署（学会：Docker、K8s 编排）
- 目标：把整个 Agent 打成 Docker 镜像，部署到 K8s 集群。
- 产出：`Dockerfile` + `k8s/deployment.yaml` + 服务化暴露。
- 验收：`kubectl get pods` 能看到你的 Agent 在跑，并通过接口访问。

## 五、关键技术点（面试可能被问）

1. **RAG 是什么？为什么需要它？** —— 解决大模型知识过时、幻觉、私有知识无法接入的问题。
2. **向量检索原理** —— 文本转 Embedding，用余弦相似度找最相关内容。
3. **Function Call / 工具调用机制** —— LLM 输出结构化指令，程序执行后把结果再喂回给 LLM。
4. **Agent 的观察-推理循环（ReAct）** —— 思考 → 行动 → 观察 → 再思考，直到解决。
5. **Docker 与 K8s 的区别** —— Docker 管单个容器，K8s 管一群容器的编排、扩缩容、自愈。
6. **Agent 安全性** —— 如何防止 LLM 执行危险命令（白名单、只读优先、二次确认）。
